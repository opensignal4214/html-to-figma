# Plan — 3.7 Emit the rendered font, not the first-listed one

Status: **approved (auto-proceed)** · Roadmap 3.7 · Effort: M

## Problem

Found by the 2.5 D content-weighted metric. For `font-family: Inter, Arial,
sans-serif` on a machine without Inter installed:

- Chrome renders the first **installed** family, Arial. Every measured rect
  (widths, line wraps, line-box heights) is therefore Arial geometry.
- The builder walks the stack in order and loads the first family **Figma**
  has: Inter, which Figma always has.

The Figma text is then set in a different font than the one its box was
measured with. It comes out wider or narrower, can wrap differently, and
sits at different heights. On the pricing Hero this costs about half the
content fidelity (52% vs ~96% on the cards). The same happens for any brand
font the extraction machine lacks, and it varies from machine to machine.

## Design

1. **Resolve the rendered family per text node** at extraction time, using
   CDP `CSS.getPlatformFontsForNode(nodeId)`, which returns
   `[{ familyName, postScriptName, glyphCount, isCustomFont }]` for the text
   actually drawn. Take the family with the most glyphs. This is Chrome's own
   answer, with no heuristics.
   - The walker runs inside `page.evaluate`, which has no CDP access. So after
     the walk, a Node-side pass (like the 2.2 raster post-pass) maps each TEXT
     node back to its DOM text node and queries CDP. Each TEXT node gets a
     transient `data-h2f-id` on its parent element, which is removed after.
2. **Tree schema (additive):** `text.renderedFamily?: string`, set only when
   it differs from the stack's primary family (case-insensitive). Output
   stays byte-identical when the intended font rendered, keeping the change
   minimal for machines that have the fonts.
3. **Builder:** when `renderedFamily` is present, try it first and then
   continue down the authored stack. Figma then matches the measured
   geometry, and if Figma lacks the rendered family, the authored stack
   still applies.
4. **Font report (3.1):** list mismatches, for example "Inter was not
   installed; text rendered and measured with Liberation Sans (Arial). Install
   Inter or add an @font-face to convert with Inter." That message is the
   actionable fix for designers.
5. **Opt-out:** `--font-source authored` restores the old behavior (use the
   authored stack even though the geometry was measured with another font).

Figma family naming: Chrome reports platform names ("Liberation Sans" for the
Arial alias on Linux, "Arial" on macOS). Map only exact metric-compatible
clones (Liberation Sans→Arial, Liberation Serif→Times New Roman, Liberation
Mono→Courier New, Arimo→Arial, Tinos→Times New Roman, Cousine→Courier New)
in `src/figma-fonts.js`, so Figma gets a family it knows with identical
metrics. Other platform families pass through unchanged.

## Tests (TDD)

- Unit, `pickRenderedFamily(platformFonts, stack)`: most glyphs wins; returns
  null when it equals the primary family; alias mapping applied; ties are
  handled deterministically.
- Unit, builder via the emulator: with `renderedFamily`, `loadFontAsync` is
  tried with it first, then the stack, with the correct fallback order.
- E2E: a fixture using `font-family: "Definitely Missing Font", Arial` →
  `renderedFamily` is Arial (or its alias) and the report flags it.
- Gate: pricing Hero content fidelity goes from ~52% to ≥ 90% in this
  environment. Raise the pricing `--assert-component-fidelity` from 45 to the
  newly measured floor.

## Baseline impact

In environments without Inter (this container, CI), the pricing text nodes
gain `renderedFamily`: an intentional, additive diff. With Inter installed
there is no diff.

## Risks

- CDP node mapping for text split across inline elements: use the text
  node's parent element. Its platform fonts cover all its text, and the
  dominant family is what matters.
- Per-node CDP calls are slow on large pages: batch them and dedupe by
  element.
