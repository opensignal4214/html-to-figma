# Plan — 8.2 HTML fragment / stdin input

Status: **shipped** · Roadmap 8.2 · Effort: S

## Problem

The tool only accepts a file path or URL (`page.goto`). The core use case is a
user *dropping HTML* — often a snippet pasted on stdin, not a saved file.

## Design

- `extractTree(input, opts)`: if `opts.html` (raw HTML string) is provided, use
  `page.setContent(html, { waitUntil })` instead of `page.goto(toUrl(input))`.
  Everything after (css-map injection, evaluate, rasterize, prune) is identical.
  A bare fragment is fine — the browser wraps it in html/body.
- `htmlToFigma`/programmatic: pass `{ html }` through (already flows via opts).
- CLI: `--stdin` reads all of stdin into `opts.html`; then the positional input
  is optional. Keep file/URL path as-is.

Relative asset URLs in a fragment have no base to resolve against — document
that inline HTML should use absolute URLs or `data:` URIs (same guidance the
skill already gives).

## Test plan (TDD)

1. e2e: `extractTree(null, { html: '<div data-figma-component="X">hi</div>' })`
   → tree with component `X` and the text. (No file on disk.)
2. Baseline: unaffected (file path still works; pricing-card identical).
3. Manual: `echo '<button ...>' | node bin/html-to-figma.js --stdin -o out`.

## Risk / rollback

Additive: the goto path is unchanged when `opts.html` is absent. One commit.
