# Plan — 2.3 True-Figma verification loop

Status: **harness shipped; awaiting FIGMA_TOKEN + file key to run** · Roadmap 2.3 · Effort: M

## Goal

Confirm (or refute) the best-effort Figma matrices flagged throughout —
rotation pivot/sign (1.2), crop `imageTransform` (1.5), linear/radial gradient
transforms (4.2) — against the **real Figma renderer**, not our simulation.

## Hard constraint (why it's semi-automated)

The Figma REST API is **read-only** for canvas content: it can export/read but
**cannot create nodes**. Getting our design into Figma requires the Plugin API
running inside Figma, and there is no official headless runner. So one human
action is unavoidable: **paste `figma-script.js` into Scripter and Run, once
per batch**. Everything else is automated with a read-only `FIGMA_TOKEN`.
(Headless Figma automation is out of scope — fragile / ToS-risky.)

## Design — `test/figma-verify.js`

Inputs: `FIGMA_TOKEN` (env), `--file <key>`, `--source <html>`,
`--name <component>` (find the exported node by name; fallback to the first
top-level child), `--width`.

Flow:
1. Render `--source` in headless Chromium; full-page screenshot at `--width`
   (reuse the preview harness's browser + screenshot).
2. `GET /v1/files/:key` → walk the document JSON, **find the node by name**
   (`findNodeByName`, pure + unit-tested).
3. `GET /v1/images/:key?ids=<id>&format=png&scale=2` → returns a temporary URL;
   download the PNG.
4. Rasterize both PNGs to a shared canvas in-browser and **pixel-diff** (reuse
   the unit-tested `pixelDiff` spec / the preview's in-page diff).
5. Report overall + note whether the flagged constructs match; non-zero exit if
   below a threshold, so it can gate later.

Pure, testable now (no token): `findNodeByName`, the Figma image-URL request
builder, and the diff (already covered by `pixel-diff.test.js`). The REST +
browser orchestration runs once the token + file key are provided.

## Risk / rollback

New standalone harness; touches nothing in the extract/generate/build path, so
zero baseline risk. The verification *findings* may trigger follow-up fixes to
the flagged matrices — each its own TDD change.
