# Plan — 2.5 Spec-faithful verification without a Figma account

Status: **approved (auto-proceed)** · Roadmap 2.5 · Effort: M–L

## Why

The real-Figma loop (2.3) needs a Figma account. Before that, we need tests whose
ground truth is **Figma's own published semantics**, not our assumptions.
Auditing the current harness against Figma's official sources showed it was
partly **circular**: it checked the builder's assumptions against themselves.

Findings (all reproducible without Figma):

| # | Finding | Evidence |
|---|---|---|
| 1 | **Rotation pivot is wrong.** Figma rotates about the node's **top-left** and `rotation` only rewrites the 2×2 part of `relativeTransform` (x/y untouched). The builder assumed rotation about the center, so rotated boxes drift in real Figma. | `@figma/plugin-typings` doc on `rotation` / `relativeTransform` |
| 2 | **Preview rotation was circular.** It rendered `rotate(θ, w/2, h/2)`, i.e. the builder's own assumption. | `test/preview.js` |
| 3 | **Radial preview ignored the emitted matrix.** It hardcoded `r=0.5`. Decoded with the oracle, the builder's matrix has radius **1.0**; CSS default `farthest-corner` needs **≈0.707**. | `@figma-plugin/helpers` `extractRadialOrDiamondGradientParams` |
| 4 | **Linear gradient direction is wrong on non-square boxes.** Angle trig was done in normalized space, which is only valid for W = H. The handles also sit off the centerline (row 1 is missing the +0.5 offset). | CSS gradient-line spec vs oracle `extractLinearGradientParamsFromTransform` |
| 5 | **Fidelity metric is diluted.** It is scored over the whole page, which is mostly empty background. The radial fixture reads **98.9 %** overall but **4.6 %** for the component. | `test/preview.js` measurement |

Crop `imageTransform` decodes correctly under the oracle and stands.

## Ground truth used (no Figma account needed)

1. **Official `@figma/plugin-typings`**: Figma's API reference shipped as
   JSDoc. It is authoritative for property names, enums, paint shapes, and
   `rotation`/`relativeTransform` semantics (`rotation = atan2(-m10, m00)`,
   pivot at top-left, auto-layout children ignore `m02/m12`).
2. **`@figma-plugin/helpers`**: a widely used community library whose
   decoders (`extractLinearGradientParamsFromTransform`,
   `extractRadialOrDiamondGradientParams`, `extractImageCropParams`) encode the
   Figma matrix conventions and were built against real Figma. It is used only
   as an **independent oracle**, never by the builder.
3. **CSS specifications**: the gradient-line length and endpoints, radial
   shape and size keywords, and `object-fit`/`object-position` geometry. This
   is the browser side of the comparison.

Independence rule: the builder, the oracle, and the renderer must not share
transform code, so a wrong convention cannot hide itself.

## Deliverables

### A. Type conformance against the official typings
`npm run test:types` runs `tsc --noEmit --checkJs` on `src/runtime/builder.js`
with `@figma/plugin-typings` as the `figma` global. This catches nonexistent
properties, invalid enum values, and malformed paints/effects: errors real Figma
would throw at runtime. Wired into `npm test` and CI.

### B. Transform oracle tests, then fix the matrices (TDD)
`test/unit/figma-oracle.test.js` decodes every emitted matrix with the official
formula or the oracle and asserts the **CSS pixel geometry**:
- **Rotation**: compose the emitted `relativeTransform` per the official
  docs. The rotated box's center and corners must equal the CSS box. Expected
  **red**; fix by emitting `relativeTransform` that rotates about the center.
- **Linear**: decoded `start`/`end` must equal the CSS gradient-line endpoints,
  property-tested across angles and aspect ratios. Expected **red** on non-square
  boxes; fix by building the matrix from pixel-space CSS endpoints, with row 0 as
  the exact CSS `t` functional and row 1 putting the centerline at `gy = 0.5`.
- **Radial**: decoded center and radii must equal the CSS `shape`/`size`/`at`
  result (circle and ellipse; `closest-side`, `farthest-side`,
  `closest-corner`, `farthest-corner`). Expected **red**; fix by parsing the
  descriptor and building the matrix from pixel-space radii.
- **Crop**: decoded position and size must equal `object-fit: cover` plus
  `object-position` geometry. Expected **green** (regression lock).

`parseLinearGradient`/`parseRadialGradient` gain optional `(w, h)` parameters,
defaulting to `1, 1`, so existing square-case unit tests keep passing.

### C. Spec-faithful emulator + renderer
- The mock and preview store **`relativeTransform` as the source of truth**. `x`,
  `y`, and `rotation` are the documented views: setting `rotation` rewrites only
  the 2×2 part, and auto-layout children ignore the translation.
- The preview renders nodes with SVG `matrix(m00 m10 m01 m11 m02 m12)`, with no
  rotation assumption.
- The preview renders paints from the **oracle decoding**: linear gradients as
  `userSpaceOnUse` start/end, radial as a transformed ellipse, crop as the decoded
  image position and size.

### D. Honest fidelity metric
- **Content-weighted**: score only pixels where either render differs from the
  shared background, so empty page area cannot dilute errors.
- **Per-component gate**: every component must pass, not just the page.
- **AA-tolerant**: compare at half resolution (box-filtered) so text
  anti-aliasing noise does not mask or mimic geometry errors.
- Thresholds are set from measured current values and documented.

## Baseline impact (intentional)

Fixing the linear gradient changes `pricing-card.html → tree.json`, because the
Pro card is a non-square 135° gradient. This is an intentional, explained
baseline update. The diff must be limited to gradient `transform` values; the
saved baseline is refreshed in the same commit.

## Residual gaps (still need 2.3 / real Figma)

Figma's text engine (shaping, line breaking), font availability, the exact Auto
Layout engine, effect rendering (blur and shadow algorithms), and image
resampling. None of these can be emulated faithfully from public specs.

## Risk / rollback

Test-layer work plus three targeted matrix fixes, each shipped as its own TDD
commit. The builder changes are confined to rotation (leaf nodes only) and
gradient matrices.
