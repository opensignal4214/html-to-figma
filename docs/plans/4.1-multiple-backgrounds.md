# Plan — 4.1 Multiple background layers

Status: **draft, awaiting sign-off** · Roadmap item: Phase 4.1 · Effort: S–M

## Problem

CSS lets an element stack several background layers:

```css
background:
  linear-gradient(rgba(0,0,0,.5), rgba(0,0,0,.5)),  /* top layer (overlay) */
  url("hero.jpg");                                   /* below it */
background-color: #fff;                              /* bottom-most */
```

Today the extractor parses only the **first** `background-image` layer (into
`st.gradient` **or** `st.bgUrl`) and drops the rest. So the common "darkening
overlay on a hero image" pattern loses either the overlay or the photo.

## Does this need real Figma? No.

Unlike rotation pivot / crop `imageTransform` / radial `gradientTransform` —
where Figma applies a matrix whose convention I can't confirm without seeing it
render — this item is only about **fill stacking order**, which is fully
documented: `node.fills` is an array painted **bottom-to-top** (index 0 =
bottom). We already rely on this for the single `[solid, gradient, image]`
stack. 4.1 generalizes it to N layers. Per-layer gradient transforms reuse the
existing (already-flagged) linear/radial code — no *new* unverifiable matrix.

It is also **fully preview-verifiable**: `renderBox` already loops over *all*
`n.fills` and paints each rect in order, so a correct builder array shows the
real stack against the browser in the fidelity overlay.

## Design — additive, baseline-safe

Same strategy that worked for 4.4 per-side borders: keep the existing
single-layer keys untouched (so single-layer output stays **byte-identical**),
and add a new `bgLayers` array **only when there is more than one layer**.

### Tree schema (additive)

New optional field on `style`, present only for multi-layer backgrounds:

```
style.bgLayers: [
  { kind: 'gradient', gradient: { stops, transform, type? } },
  { kind: 'image', base64, scaleMode: 'FILL'|'FIT'|'TILE', scalingFactor? },
  …
]  // CSS order: index 0 = TOPMOST layer
```

`style.background` (solid color) is unchanged and remains the bottom-most fill.
When `bgLayers` is present, `style.gradient` / `style.backgroundImage` are NOT
set (they stay the single-layer representation).

### `mapBoxStyle` (css-map.js, pure/unit-tested)

- `splitTopLevel(background-image)` → layer strings (commas inside
  `linear-gradient(...)`/`rgba(...)` are not top-level, so a single gradient is
  one segment → single-layer path, baseline safe).
- **≤ 1 layer** → today's exact path (`st.gradient` or `st.bgUrl` +
  `st.bgScaleMode`). Extracted via the shared `layerScaleMode()` helper so the
  computed value is identical to before.
- **> 1 layer** → parse each layer to `{kind:'gradient', gradient}` or
  `{kind:'image', url, scaleMode}` using index-matched `background-size` /
  `background-repeat` (CSS repeats short value lists). Store as `st.bgLayers`.

### Extractor (extract.js)

Mirror the existing `bgUrl` fetch: for each `bgLayers` image layer, fetch its
URL → inline `base64` (and `scalingFactor` for TILE), delete the transient
`url`.

### Builder (runtime/builder.js)

`__frameFills`: when `st.bgLayers` present, push `[solid?, ...bgLayers reversed]`
— reversed because CSS is top→bottom but Figma fills are bottom→top. Factor
`__gradientPaint()` / `__imagePaint()` helpers and reuse them for the existing
single-layer paths too (dedupe).

### Preview (test/preview.js)

No change required — `renderBox` already iterates all fills in order.

## What is explicitly out of scope

- `background-position` per layer (single-image position is already a separate
  follow-up under 1.5).
- `background-blend-mode` between layers (rare).
- More than a handful of layers (works, but not optimized).

## Test plan (TDD)

1. **Unit** (`css-map.test.js`):
   - single gradient → `st.gradient` set, `st.bgLayers` undefined (baseline
     guard).
   - `linear-gradient(...), url(...)` with `background-size: auto, cover` →
     `st.bgLayers` length 2, `[0].kind==='gradient'`, `[1].kind==='image'`,
     `[1].scaleMode==='FILL'`, solid `background` retained.
2. **Baseline**: pricing-card `tree.json` byte-identical (its featured card has
   a single gradient → single-layer path).
3. **e2e** (`integration/extract.test.js`): a gradient-over-image fixture →
   assert two `bgLayers` on the node, image layer carries `base64`.
4. **Mock**: generated script runs (fills array applied without error).
5. **Preview**: gradient-over-image fixture overlay has no ghosting; record the
   fidelity %.

## Risk / rollback

Additive: single-layer path is unchanged and baseline-guarded, so risk is
isolated to multi-layer inputs. If a layer fails to parse/fetch it is skipped
(the rest still render). Rollback = revert the one commit.
